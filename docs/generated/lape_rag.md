# Lape Library RAG — Semantic Search Documentation

`scripts/build_lape_rag.py` builds a local ChromaDB vector index from the symbol docs and repository documentation. `scripts/search_lape_rag.py` exposes it as a standalone CLI. The `search_lape_rag` MCP tool exposes the same search through Claude's tool interface.

---

## What it does

The RAG system provides semantic (meaning-based) retrieval over:

- All 8623 Lape/SRL-T/WaspLib/Farm library symbol docs generated by `build_lape_lib_docs.py`
- Repository documentation: `README.md`, `CLAUDE.md`, `AGENTS.md`, all `docs/**/*.md` files

Unlike the keyword/fuzzy `search_lape_libs` tool, semantic search finds relevant results even when the query words don't appear literally in the index. Natural language queries such as "how do I withdraw items from the bank" or "which API handles walking to map objects" return relevant symbol and doc chunks.

**RAG retrieval is a finding aid, not authoritative documentation.** Source inspection always wins over summaries and embeddings.

---

## Backend and embedding model

| Component | Choice | Notes |
|-----------|--------|-------|
| Vector store | ChromaDB (local persistent) | Stored in `.cache/lape_rag/` (gitignored) |
| Embedding model | `all-MiniLM-L6-v2` | 384 dimensions, via `sentence-transformers` |
| Embedding method | CPU (no GPU required) | First run downloads ~90 MB model; subsequent runs use local cache |
| Similarity metric | L2 distance → similarity score | Score = `1 − distance/2`, range [0, 1] |

The model download is handled automatically by `sentence-transformers` on first run and cached at the default HuggingFace cache location.

## Chunk types

| Chunk type | Content | Source |
|------------|---------|--------|
| `symbol_doc` | Functions, procedures, methods, constants, variables, enums, aliases | `lape_lib_symbol_docs.jsonl` |
| `record_doc` | Record type declarations | `lape_lib_symbol_docs.jsonl` |
| `field_doc` | Record field declarations | `lape_lib_symbol_docs.jsonl` |
| `repository_doc` | README, docs/*.md sections | Repo markdown files |
| `policy_doc` | CLAUDE.md, AGENTS.md sections | Operating instruction files |

## Build commands

### First build (or after a library update)

```
py scripts/build_lape_lib_docs.py
py scripts/build_lape_rag.py
```

The first command generates `docs/generated/lape_lib_symbol_docs.jsonl` from the existing symbol index. The second builds the vector database in `.cache/lape_rag/`.

Rebuilding always starts clean (deletes and recreates the ChromaDB collection).

### When to rebuild

- After any library update under `%LOCALAPPDATA%\Simba\Includes\` (regenerate the symbol index first, then rebuild docs and RAG)
- After a rescan of the symbol index (`docs/generated/lape_lib_symbol_index.jsonl`)
- After significant changes to `docs/` or `README.md` / `CLAUDE.md` / `AGENTS.md`
- After updating `build_lape_lib_docs.py` or `build_lape_rag.py`

## Fallback CLI search

```
py scripts/search_lape_rag.py "how do I withdraw items from the bank" --limit 8
py scripts/search_lape_rag.py "how do I check uptext" --limit 8
py scripts/search_lape_rag.py "which API handles walking to map objects" --limit 8
py scripts/search_lape_rag.py "TRSObjectV2 inherited fields" --limit 8
py scripts/search_lape_rag.py "StrToInt" --limit 8
py scripts/search_lape_rag.py "bank withdraw" --json --limit 8
```

### Optional filters

| Flag | Values | Effect |
|------|--------|--------|
| `--kind` | field, method, function, record, … | Filter to a specific symbol kind |
| `--source-root` | SRL-T, WaspLib, Farm, repo_docs | Filter by library |
| `--chunk-type` | symbol_doc, record_doc, field_doc, repository_doc, policy_doc | Filter by content type |
| `--json` | (flag) | Emit results as JSON array |

## MCP tool: `search_lape_rag`

When the MCP server is active in a Claude session, the `search_lape_rag` tool is available directly:

```
search_lape_rag(query="how do I withdraw items from the bank", limit=8)
search_lape_rag(query="check uptext before clicking", limit=8)
search_lape_rag(query="TRSObjectV2 fields", kind="field", limit=10)
search_lape_rag(query="walking to map objects", source_root="SRL-T", limit=8)

The tool returns a JSON object:

```

## Limitations

1. **Not a substitute for source inspection.** RAG summaries are mechanically generated or short structured descriptions. Exact signatures, parameter order, side effects, and return conditions must be verified against the source files at `%LOCALAPPDATA%\Simba\Includes\`.

2. **Lape built-ins are absent.** `StrToInt`, `IntToStr`, `Length`, `WriteLn`, and other Lape interpreter built-ins are not defined in any scanned library file and will not appear in RAG results.

3. **Weak or empty results are inconclusive.** They do not prove a symbol is absent. Retry with a rephrased query, or use `search_lape_libs` for a keyword search. If the search is empty for built-in names, that is expected (see above).

4. **Score interpretation.** Scores are normalized L2 distances, not calibrated probabilities. A score of 0.85+ indicates strong semantic overlap; 0.5–0.7 is plausible but off-target results are common; below 0.5 the result is weakly related. Always inspect the actual `text` field rather than relying solely on score.

5. **Index staleness.** The RAG index is a snapshot built from `lape_lib_symbol_docs.jsonl` at build time. If the library changes, rebuild: `py scripts/build_lape_lib_docs.py && py scripts/build_lape_rag.py`.

6. **Record inheritance is not explicit in chunk text.** The chunk for `TRSObjectV2` does not list inherited fields from `TRSMapObject`. Use `search_lape_libs(query="TRSMapObject", kind="field")` for inherited fields.

7. **`.cache/lape_rag/` is gitignored.** The vector database is a local build artifact and is not committed to the repository. Every developer must build it locally. See "Version control" below.

## Troubleshooting

**`FileNotFoundError` on `.cache/lape_rag/`:**
The RAG index has not been built yet, or was deleted. Run:
```
py scripts/build_lape_lib_docs.py
py scripts/build_lape_rag.py
```

**`ModuleNotFoundError: No module named 'chromadb'`:**
```
py -m pip install chromadb sentence-transformers
```

**`search_lape_rag` is not in Claude's tool list:**
The MCP server was not loaded when the session started, or the RAG index wasn't built when the server started. Rebuild the index, then restart the Claude session.

**Results seem wrong or irrelevant:**
- Rephrase with more specific language or a known symbol name.
- Use `--chunk-type symbol_doc` to restrict to library symbols only.
- Use `search_lape_libs` for exact/fuzzy keyword search as a cross-check.
- Verify any result against the source file at `%LOCALAPPDATA%\Simba\Includes\` + `file_path`.

**`HF_HUB_DISABLE_SYMLINKS_WARNING` warning on Windows:**
This is cosmetic. Set `$env:HF_HUB_DISABLE_SYMLINKS_WARNING=1` to suppress it. The model still downloads and caches correctly.
